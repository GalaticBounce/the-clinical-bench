# Clinical Bench website

Static marketing site for theclinicalbench.com on Cloudflare Pages. Push to `main` deploys.
Build command on Pages is none, so **generated pages are committed**. Two Pages Functions
handle the forms (`functions/api/`). Two more return 404 for `/content/` and `/docs/` so
sources and internal documents in this repo are never served.

## Layout

```
index.html, clinicians/index.html, privacy/index.html   hand-authored. Edit directly.
content/insights/<slug>.md      published post sources (status: published)
content/drafts/<slug>.md        drafts awaiting review (status: ready for review | approved | rejected)
content/drafts/<slug>.sources.txt   gate 17 source file for posts that cite figures
content/drafts/preview/         git-ignored HTML previews of drafts
content/calendar.yaml           the content calendar the runner reads. Jamie edits it.
content/queries.yaml            the queries the weekly visibility check searches
insights/                       GENERATED by build.js. Never edit by hand.
sitemap.xml, insights/rss.xml   GENERATED. llms.txt: only its "## Insights" section is generated.
build.js                        node build.js | --check | --preview <draft.md>
docs/                           strategy, analysis, audit logs. Not served.
<32 hex chars>.txt              IndexNow key. Public by design. Not a secret.
```

## Commands

```bash
node build.js            # regenerate insights pages, index, rss, sitemap, llms.txt section
node build.js --check    # exit 1 if a build would change anything (reproducibility proof)
python3 ~/.claude/scheduled-tasks/clinical-bench-seo-publisher/preflight.py     # can the runner run
python3 ~/.claude/scheduled-tasks/clinical-bench-seo-publisher/calendar.py status
python3 ~/.claude/scheduled-tasks/clinical-bench-seo-publisher/calendar.py approve <slug>
python3 ~/.claude/scheduled-tasks/clinical-bench-seo-publisher/gates.py <slug> --draft
python3 ~/.claude/scheduled-tasks/clinical-bench-seo-publisher/seo_audit.py
```

## The routine

`clinical-bench-seo-publisher` in the scheduled tasks. Spec and scripts in
`~/.claude/scheduled-tasks/clinical-bench-seo-publisher/`. Weekdays: release what is
approved and due, draft the next slot 4 to 10 days out, Mondays audit and log visibility.
It never approves its own drafts. Approve with `calendar.py approve <slug>`.

## Rules

- No em dashes, no comma before "and", Australian English, no puffery. `gates.py` enforces it.
- No named clinician or client, no testimonial, no unsourced percentage or dollar figure.
- Never describe Clinical Bench as a clinical service, a CRO, or running trials.
- Secrets live in the Cloudflare Pages dashboard. Never in a file here.
- `assets/*` is cached immutably. Rename or `?v=` when changing an asset.
- `_Inbox/` is Jamie's drop folder, git-ignored, not part of the site.

## Liability posture (11 Sep 2026)

Jamie's instruction: maximise protection. `docs/LIABILITY-REVIEW.md` ranks the exposures
(labour hire licensing, superannuation on contractor fees, uninsured advice, endorsement
law, missing contracts, privacy) and `docs/CONTRACT-TERM-SHEETS.md` is the brief for a
lawyer. Site and content rules that follow: never legal or regulatory advice, every post
carries the disclaimer, no endorsement language anywhere, no "supply a worker" framing.

**Commercial model under review (11 Sep 2026).** Jamie is exploring a pure introducer
model: clinicians contract directly with companies, Clinical Bench charges the company
for the search and connection, never pays or manages the clinician. `docs/INTRODUCER-MODEL.md`
has the analysis and fee options. Until decided, site copy still describes the
contracting model ("we handle the contracting and invoicing") and posts must stay neutral
on who contracts with whom and who pays whom.
